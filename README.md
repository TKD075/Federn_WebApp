# 動機
昨年個人学習のために何か作ってみたく、ちょうど就活ということでポートフォリオを題材に選択しました。  
[該当リポジトリ](https://github.com/TKD075/WebSitePractice), [該当ポートフォリオ](https://tkd075.github.io/WebSitePractice/)  
こちらはHTML/CSS、それにほんの少しのJavaScriptで構成されているのですが、フレームワークも取り入れずCSSも全て自作したため、UIもUXもお粗末なGitHubPagesとなっていました。  
  
元々このWebサイトには満足しておらず、一旦これで完成としておくが後でリファクタリングしようと考えていました。  
理由としましては、やはりエンジニアたるもの*Full Stack*で*modern*な技術を取り入れた*rich*なものを作ることで**圧倒的成長**ができると考えていましたし、基礎基本が重要だと理解している上で最新のトレンドをある程度キャッチアップしていく、その技術を実際に使ってみる経験は社会に出る上で必要かつ自分に不足しているものだと実感していたからです。  
加えて、個人で全て好きにできる制作物なのにドメインにgithubが含まれていること・githubPagesに依存していることが一目で分かる状況を好ましく思っていないため、ドメインを自分の設定したもので公開できるようにしたかったということもリファクタリングしたい理由の一つでした。  
  
# 制作の進行
近年生成AIの台頭によりコーディングがAIに置き換わりつつあることを鑑みてVibe Codingに挑戦しました。  
ディープリサーチや仕様策定をGPT5に任せ、コーディングはCodexにさせてみました。  
プロンプトで特に気を付けた点としては、ディープリサーチ用のチャットに仕様策定の内容を出力させない、仕様策定のチャットに実装内容を出力させない、といった役割の分担を明確にしたことです。これによって異なった役割のAIの出力が矛盾すること、トークン不足によって過去の出力と矛盾すること等を削減できたのではないかと考えています。  
  
  
# 技術スタック
GitHubにはLanguagesの欄があるため使用技術は一目で分かりますし理由も大層なものではないですが、それぞれの選定理由を記していきます。  
  
## インフラ(AWS, Docker, GitHub)
### AWS
元々可能な限り自分の手元で全て賄いたかったため、私物のRaspberry Pi5をWebサーバー兼DBサーバーとして運用しようと考えていました。  
しかし現在実家暮らしなこと、プロバイダの都合上ポート開放が不可能なことが分かったため、元から興味のあったAWSを使ってみようと思い立ち、アカウント開設から6か月は実質無料でサーバーを使えることも相まって転居するまでの繋ぎとしてAWSを採用することにしました。そのためサーバーは転居後AWSからPiに移行する予定です。  
使用しているのはEC2になります。  
### Docker
昨年コンテナという概念を知り、その便利さに驚愕したこと、LinuxとWindowsという2つのOSで開発することからDockerを使用しています。  
### GitHub
GitHubActionsでCI/CDを管理しようと考えています。AWSに無料でcloneする方法が不明瞭だったためまだ実行できていませんが、近いうちに行う予定です。  

## フロントエンド(React + TypeScript)
まずフルスタックWebアプリケーションを作成しようということで、フロントエンドではTypeScriptを使いたいと考えていました。  
そのためTypeScriptをベースとしたフレームワークを探し、Reactにたどり着きました。  
Next.jsやNode.js、Vue.js等の選択肢もあったのですが、近年需要が増加しているらしいということでReactを選択しました。  
現在はTypeScriptで型定義を行い、`npm run build` で `tsc` によりモジュールをビルドする構成に移行しています。  

## バックエンド(Go)
バックエンドに何を採用しようか悩みました。主な候補は4つで、就活中に使用率が高いように感じたJava、入門しやすくAPIを扱いやすいPython、日本語のリファレンスが多くベンチャー企業で採用されている傾向の高いRuby(on Rails)、軽量で高速なGo。  
動機からRubyかGoを採択したく、Rubyは別途実施しているクローズドの勉強会で使用していることからGoを選択しました。  

## データベース(PostgreSQL)
無料で使えるRDBMSを利用しようと考えていました。ディープリサーチの結果、この条件にマッチした上で社会で利用されている割合がどうやら高いらしいPostgreSQLを選択しました。  


# 実装内容
そもそもこのWebアプリは求める用途が2つあり、1つはポートフォリオとして外部公開すること、もう一つは自分が使いたい機能をモリモリ継ぎ足して魔改造できるようにすること、この2点です。  
そのためホーム画面と制作物の公開、自己紹介の3ページは少なくとも必要でした。  
まだ叩き台のため中身も簡素ですが、取り敢えず外部公開用としてモノは作れたかなといった状況です。今後どんどん機能を追加する予定です。
